# Kodi UX principles — Apple tvOS rules, mapped to the Kodi box

Source: Apple tvOS Human Interface Guidelines, as applied to PLAN 8.11 (2026-11-25).
Apple TV is the reference. Test every screen with the real remote, on the Hisense, from the sofa (about 3 m).

1. **Focus is the cursor.** One item is clearly focused (scaled, lit). Every screen has a predictable first focus. Never leave the user hunting for where they are.
2. **Directional only.** Everything is reachable with up, down, left, right, OK and Back. No screen needs a mouse, a keyboard, or a long text field.
3. **Shallow.** Aim for 2 levels, never more than 3. Goal from PLAN 8.11: any film in 3 clicks or fewer.
4. **Back is sacred.** Back always goes up one level. Home always goes to the top.
5. **Content is the interface.** Big posters in rows, little chrome. The top row is a shelf of things to watch, not a menu of settings.
6. **Fixed vocabulary.** The same key always does the same thing.
   - OK plays or opens.
   - Long-press OK, or Info, shows details and options.
   - Play/Pause toggles playback.
   - Back goes up one level.
7. **10-foot rules.** Large text, high contrast, nothing important near the screen edges. Judge from 3 m.
8. **Feedback within a moment.** Every press visibly does something (the "I ain't dead" rule). Kodi lag on this box is the biggest risk: every widget and fanart choice must pass the sluggishness test.

## How we apply them (the process, from the Sanchalak lessons)
- Write the task list (5 lines at most) before any screen. The navigation is those lines and nothing else.
- Build one screen, then use it for a day before building the second.
- Every new feature names the screen it extends and what it removes or merges. If it needs a new tab, rewrite the task list first.
- Customise an existing skin (Arctic Zephyr), never write one from scratch.
- Schedule a deletion pass: remove whatever goes unused.
